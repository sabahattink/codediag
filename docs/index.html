Diagnose your code before you ship.

One command. Five analyzers. One score.

CodeDiag reads a Node.js, NestJS, Express, Fastify, Hono, or Next.js project on your machine and returns a 0–100 health score that accounts for every point it takes. Each finding carries a stable rule ID, a file and line when there is one, and a suggested fix.

$npx @sabahattink/codediag scan .

Or npm install -g @sabahattink/codediag for a global codediag command.

  • Node.js 20.19+
  • No account, no upload
  • Offline with --no-audit
  • MIT licensed

A readout that shows its work

The terminal report leads with the grade and the weighted score, then one bar per analyzer, then critical findings and warnings with their location and fix. --verbose adds info findings and the per-rule breakdown behind each bar.

  1. Grade and weighted total. 82×0.25 + 0×0.30 + 63×0.20 + 0×0.15 + 80×0.10 = 41.1, rounded to 41.
  2. One bar per analyzer, each scored 0–100 on its own: twenty cells, five points each.
  3. Counts by severity. Info findings stay folded until you pass --verbose.
  4. A stable rule ID. codediag explain dynamic-sql-query describes the rule and shows how to suppress it.
  5. Location and fix. CodeDiag recommends; it never edits your files.

Five analyzers, weighted by what breaks in production

CodeDiag detects the stack, walks the files once, and parses them into one ts-morph project that every analyzer shares. Routes and security sinks come from the syntax tree, not regular expressions. NestJS, Express, Fastify, Hono, and Next.js get all five analyzers; plain Node.js projects get everything except API Health.

The score is arithmetic you can check

No model, no percentile, no hidden weighting. Recompute any score by hand from the report, or read scoreBreakdown in the JSON output.

  1. Every analyzer starts at 100.
  2. Each finding subtracts its severity weight: critical 25, warning 8, info 2.
  3. Repeats of one rule cost half the previous one, so a rule never costs more than twice its weight. Three critical dynamic-sql-query findings cost 25 + 12.5 + 6.25, reported as −43.8.
  4. One problem is penalized once. A finding whose root cause is also reported drops to info, is linked with causedBy, and costs nothing.
  5. Nothing to evaluate scores 0. A missing package.json, or no test files at all, sets that analyzer to 0.
  6. The total is the weighted average, rounded and graded.

Gate pull requests on the score

The GitHub Action carries its own bundle: no npm install, no secrets, and no write access beyond the pull request comment you opt into.

.github/workflows/codediag.yml
on:
  pull_request:

permissions:
  contents: read
  pull-requests: write

jobs:
  codediag:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: sabahattink/codediag@v0
        with:
          threshold: 80
          comment: true
  • Critical findings and warnings become annotations, up to 50 per run, next to a job summary.
  • JSON and SARIF reports, plus score, grade, report, and sarif outputs for later steps.
  • Exit 1 below the threshold, 2 when configuration or scanning fails.
  • Elsewhere: npx @sabahattink/codediag scan . --ci --threshold 80. Action guide

Accept findings on the record

Three ways to decide which findings count, and none of them hides anything. Suppressed and baseline findings stay in the JSON and SARIF reports; they stop affecting the score, thresholds, and annotations.

In source, with a reason
// codediag-ignore-next-line unsafe-dynamic-code -- plugin code is signed and sandboxed

No reason, no suppression: a directive without one is not applied and is reported as suppression-missing-reason. One that matches nothing becomes unused-suppression.

For the whole project
rules:
  missing-swagger: off      # internal service without public API docs
  open-cors: critical       # stricter than the default warning

In .codediag.yml: off, info, warning, or critical. An unknown rule ID fails the scan instead of being ignored.

For code that already exists
codediag scan . --update-baseline .codediag-baseline.json
codediag scan . --ci --threshold 80 --baseline .codediag-baseline.json

Findings are matched by a line-independent fingerprint, so moving code keeps them matched and only new findings fail the gate. The Action takes the same file as baseline:. Suppressions and baselines

The same engine, inside VS Code

The extension runs the analyzers locally and publishes located findings to the Problems panel. The HTML report, the fix plan, and the AI review prompt open in the editor.

  • Scan on save is opt-in (codediag.scanOnSave) and never runs the package manager; it reuses the last audit, so scores stay consistent.
  • Disabled in untrusted and virtual workspaces. Findings outside the workspace are not published.
  • New in 0.6: quick fixes that suppress a finding with a reason or explain its rule.
  • Until Marketplace publishing, install the .vsix from a CI run. Extension guide

New in 0.6

More frameworks and sinks, secrets outside code, and reports you can compare over time.

  • Fastify API analysis

    Fastify routes join NestJS, Express, and Next.js in the API Health analyzer.

  • JWT and session misconfiguration

    algorithms: ['none'], ignoreExpiration: true, and cookies set without httpOnly or secure.

  • Template injection and prototype pollution

    Request data compiled as a template or used as an object path, recursive merges that copy __proto__, and spawn(..., { shell: true }) with non-literal arguments.

  • Secrets in config files

    JSON, YAML, Dockerfiles, .npmrc, and committed .env files, with the secret values redacted in reports.

  • Compare two scans

    The score delta per analyzer and the new and fixed findings since a previous JSON report, in every output format, with a change panel in the HTML report.

    --compare previous.json

  • Changed files only

    Report and score only the findings in files changed since a Git ref, such as origin/main, including staged and untracked files.

    --changed-since origin/main

  • VS Code quick fixes

    Suppress a finding with a reason, or explain its rule, straight from the editor’s quick fix menu.

Where CodeDiag fits

A fast, explainable health check for Node.js backends, not a replacement for a linter or a full SAST platform. Run it next to them.

Your code stays on your machine

  • No upload, no account

    Analysis runs in your own Node.js process. There is no server to sign up for and nothing to send.

  • Offline when you need it

    The only network traffic is your package manager’s own audit. --no-audit or audit: false skips it.

  • Nothing changes without you

    Fix plans and AI prompts are review-only. Prompts carry diagnostic metadata, never source contents or secrets.

  • No secrets in CI

    The Action needs none. With comment: true it uses the job token to read changed files and write one comment.
