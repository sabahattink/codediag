Does a parent loader's auth check protect child routes in React Router?

Updated November 2, 2026 · React Router 7 framework mode, Remix 2

No. React Router runs the loaders of matched routes in parallel, and a form submission runs the route's action first; loaders revalidate after it. A redirect in the parent's loader can't stop either one.

Check auth in every loader and action that needs it, or use route middleware, which runs before the matched loaders and actions. Remix v2 works the same way.

Why the parent's check doesn't cover its children

React Router's own docs say it directly: matched route loaders run in parallel, so a parent loader can't "protect" child route loaders or actions through an auth check.

Actions make it worse. A submission runs the action, and only when the action completes does React Router revalidate the loader data on the page. If the parent's loader redirects at that point, the action has already done its work.

Questions

Doesn't a redirect thrown by the parent loader stop the request?

It stops the page from rendering. By then the action has already run, and the other loaders ran alongside the parent's.

Does this apply to Remix v2?

Yes. Remix v2 loads data the same way: matched loaders in parallel, and the action before loaders revalidate.

Can clientLoader or clientAction enforce auth?

No. They run in the browser, so they are never a security boundary.

Where should the check live if many routes need it?

In route middleware on a common ancestor, or in a requireUser helper called at the top of every loader and action.
